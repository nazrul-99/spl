Pointers

A pointer is a variable that holds the address of another variable. With it, a function can change the caller's variables, and a program can reach memory by address.

Practise in the lab: Lab 09 · Pointers

Variables live at addresses

A declaration such as char letter = 'A'; makes the compiler reserve a memory location for letter and store 65 in it. That location has an address, a number such as 0x180A96E8, which the program can use at run time. A pointer is a variable that stores such an address. We say the pointer points to (or references) the other variable.

Why use pointers? To let a function change variables that belong to its caller (pass by pointer, below), to work with arrays and strings efficiently (Lecture 11), and to build data structures that grow and shrink while the program runs.

Declaring and initialising a pointer


General form: data_type *pointer_name;. In int *numberPtr; the * says that numberPtr is a pointer, and int says it points to an int. In int *numberPtr, number = 20; two locations are reserved: number holds an integer, numberPtr holds an address.


A new pointer does not point anywhere valid; it holds a garbage address. Initialise it to NULL (the value 0, meaning "points to nothing") or to a real address before using it. NULL is preferred over writing 0 because it shows the intent.



The two pointer operators




& address-of
numberPtr = &number; stores the address of number in numberPtr. Now numberPtr points to number.


* dereference (value-at, indirection)
*numberPtr = 16; goes to the address held in numberPtr and stores 16 there, so number becomes 16.




The two operators undo each other: *&var is var, and &*ptr is ptr.




Printing addresses. The slide prints addresses with %08x and %d. On a 64-bit machine an address has 8 bytes and those specifiers print only part of it. Use %p with a (void *) cast. The real addresses change from run to run; the ones above come from the run that was recorded.



Passing arguments: by value and by pointer


When an ordinary variable is passed, the function gets a copy in its own memory. Changes to the copy disappear when the function returns. When an address is passed, the function can use * to reach the caller's variable and change it. This is how a function can "return" more than one value.

A word on terms. The slides call the second method call by reference, a common name in textbooks. Strictly, C always passes arguments by value; with pointers, the value passed is an address. That is why this site says pass by pointer or call by address, and calls & the address-of operator.

E1One pointer, two variables
Easy Predict the output CO4 · BCL L-4 Analyze
Give the final values of a, b and *p.
#include <stdio.h>
int main()
{
    int a = 10, b = 20;
    int *p = &a;
    *p = *p + 5;
    p = &b;
    *p = *p * 2;
    printf("%d %d %d\n", a, b, *p);
    return 0;
}
Hint
Changing *p changes whichever variable p points to at that moment.
Solution
Output: 15 40 40. While p points to a, *p = *p + 5 makes a 15. Then p is moved to b, and *p = *p * 2 makes b 40. *p is now b, so 40.
E2A pointer parameter and a value parameter
Medium Predict the output CO4 · BCL L-4 Analyze
What is printed?
#include <stdio.h>
void f(int *x, int y)
{
    *x = *x + y;
    y = 0;
}
int main()
{
    int a = 3, b = 4;
    f(&a, b);
    f(&b, a);
    printf("%d %d\n", a, b);
    return 0;
}
Hint
Only the variable whose address is passed can change. The second argument is a copy.
Solution
Output: 7 11. f(&a, b) adds 4 to a, making 7; setting y = 0 affects only the copy. f(&b, a) then adds the current a (7) to b, making 11.

E5Sort three numbers with a helper
Medium Write a program CO3 · BCL L-3 Apply
Write void order(int *x, int *y) that swaps the two values if *x > *y. Use it three times to sort three numbers in ascending order.
Hint
order(&a, &b); order(&b, &c); order(&a, &b); is enough for three numbers. Why is the third call needed?
Solution
The first two calls move the largest value into c. The third call puts the smaller two in order. (This is bubble sort with n = 3.)

E7A pointer that points nowhere
Medium Find the bug CO4 · BCL L-4 Analyze
This program crashes (or silently corrupts memory). Why?


int *p;
*p = 25;
printf("%d\n", *p);
Hint
What address does p hold before the second line?
Solution
p is never given an address, so it holds a garbage value. *p = 25 writes to that unknown location: usually a crash (Segmentation fault), sometimes damage to some other variable. A pointer must point to real memory before it is dereferenced: give it the address of a variable (p = &x;), or set it to NULL and check before use.
