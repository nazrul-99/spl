Pointer Arithmetic, Arrays and Pointers

Adding 1 to a pointer moves it to the next element, not the next byte. That one rule explains how arrays and pointers work together.

Practise in the lab: Lab 09 · Pointers

What arithmetic is allowed on pointers

A pointer holds an address, so only a few operations make sense: increment/decrement (p++, p--), adding or subtracting an integer (p + k, p - k), subtracting two pointers of the same type, and comparing pointers (p < q, p == q). Adding two pointers, or multiplying them, is not allowed.

The key rule: the integer is scaled by the size of the pointed-to type. If p is an int * holding 1000, then p + 1 is 1004, because an int takes 4 bytes. For a char * it would be 1001, for a double * 1008.

See the scaling

Pointer type

Two notes on the slides' examples. They print pointers with %u; use %p, since a 64-bit address does not fit in an unsigned int. The addition example prints ptr2 before it has been given any value, so it shows a garbage address.

Subtracting two pointers

q - p gives the number of elements between them, not bytes: the byte difference divided by the element size. It is meaningful only when both point into the same array.

The slide subtracts pointers to two separate variables, N and x. That compiles, but C defines the result only within one array; the "1" it prints depends on how the compiler happened to place the variables.

Arrays and pointers

An array name used in an expression turns into the address of its first element. So after char str[5] = {'H','E','L','L','O'}; and char *ptr = &str[0];, printing ptr and str gives the same address. Because of the scaling rule, str[i] is exactly *(str + i): base address plus i elements.

Array2

Array name versus pointer variable. The slides describe the array name as a pointer that holds the start address. It behaves like one in expressions, but it is not a variable: str = str + 1; is an error, while ptr = ptr + 1; is fine. Also sizeof(str) is the whole array (6 bytes) while sizeof(ptr) is the size of an address (8 bytes).

E1*(p + 3) versus *p + 3

Easy Predict the output CO4 · BCL L-4 Analyze

What is printed?

#include <stdio.h>
int main()
{
    int a[5] = {10, 20, 30, 40, 50};
    int *p = a;
    printf("%d %d %d\n", *p, *(p + 3), *p + 3);
    p += 2;
    printf("%d %d\n", *p, p[1]);
    return 0;
}
Hint

* binds tighter than +: *p + 3 is (*p) + 3. p[1] means *(p + 1).

Solution
10 40 13
30 40

*(p + 3) is the element three places on (40); *p + 3 adds 3 to the value 10. After p += 2, p points to a[2] (30), and p[1] is a[3] (40).

E2Pointer difference and writing through a pointer

Medium Predict the output CO4 · BCL L-4 Analyze

What is printed?

#include <stdio.h>
int main()
{
    int a[] = {5, 1, 7, 3};
    int *p = a, *q = &a[3];
    printf("%d %d\n", (int)(q - p), *q - *p);
    p++;
    *p = *p * 10;
    printf("%d %d\n", a[1], *(a + 1) + 1);
    return 0;
}
Hint

q - p counts elements, not bytes. After p++, writing *p changes a[1].

Solution
3 -2
10 11

q points three elements after p, so q - p is 3; *q - *p is 3 − 5 = −2. Then p moves to a[1] and multiplies it by 10, so a[1] is 10 and *(a + 1) + 1 is 11.

E3A char pointer into a word

Medium Predict the output CO4 · BCL L-4 Analyze

What is printed?

#include <stdio.h>
int main()
{
    char s[] = "POINTER";
    char *p = s + 2;
    printf("%c %c %s\n", *p, *(p + 3), p + 4);
    return 0;
}
Hint

Write the indexes under P O I N T E R. %s with a pointer prints from that position to '\0'.

Solution

Output: I E R. p points to s[2] ('I'); *(p + 3) is s[5] ('E'); p + 4 is the address of s[6], so %s prints the rest of the string, "R".

E7Moving the array name

Medium Find the bug CO4 · BCL L-4 Analyze

Why does this not compile, and how do you fix it?

int a[4] = {1, 2, 3, 4};
int sum = 0;
while (a < &a[4]) {
    sum += *a;
    a++;
}
Hint

Lecture 11 explains the difference between an array name and a pointer variable.

Solution

An array name is not a variable: it cannot be assigned or incremented. GCC reports lvalue required as increment operand for a++. Copy the address into a real pointer variable and move that instead.
