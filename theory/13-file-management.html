File Management

A file is a sequence of bytes on disk that outlives the program. C reaches it through a FILE pointer and a small set of functions that read or write at a moving position.

Files and streams

C views a file as a sequential stream of bytes that ends with an end-of-file (EOF) marker. Opening a file connects a stream to it; the stream is the channel between the file and the program. Three streams are opened automatically when any program starts: stdin (standard input, the keyboard), stdout (standard output, the screen) and stderr (standard error, also the screen). All of them are handled through file pointers, which is why fgets(str, 50, stdin) reads from the keyboard.

Declaring, opening and closing

FILE *the_file; declares a pointer to a FILE structure (defined in <stdio.h>); each open file needs its own pointer. the_file = fopen("my_file.txt", "r"); opens a file and returns a pointer to it, or NULL if it cannot be opened. A file in another folder needs its path, for example "D:/my_file.txt". fclose(the_file); closes it and makes sure everything written reaches the disk.

Character I/O: fgetc and fputc

ch = fgetc(fp); reads one character and moves the position forward; at the end it returns EOF. fputc(ch, fp); writes one character, from a variable or a constant: fputc('a', fp);. Declare the variable that receives fgetc as int, so that it can hold EOF (−1) as well as every character.

Formatted I/O: fprintf and fscanf

fprintf(fp, format, values…) works like printf but writes into the file. fscanf(fp, format, addresses…) works like scanf but reads from the file; it returns the number of values read, or EOF at the end of the file, which makes a natural loop condition.

Line I/O: fgets

fgets(content, 50, theFile); reads one line, or 49 characters, whichever comes first, and stores it with its '\n' and a terminating '\0'. It returns NULL at the end of the file.

fgets with the keyboard (slide 19)

stdin is a file pointer too, so fgets reads a line typed by the user exactly as it reads a line of a file.

Notice the output. There is a line break before the full stop, because fgets keeps the newline the user typed. With the second input, only the first 9 characters fit in name[10].

E1Counting lines with fgets

Easy Predict the output CO4 · BCL L-4 Analyze

The program writes a small file and reads it back. What is printed?

#include <stdio.h>
int main()
{
    FILE *fp;
    char line[50];
    int n = 0;
    fp = fopen("t.txt", "w");
    fprintf(fp, "SEU\nCSE\n2026\n");
    fclose(fp);
    fp = fopen("t.txt", "r");
    while (fgets(line, 50, fp) != NULL)
        n++;
    fclose(fp);
    printf("lines = %d\n", n);
    return 0;
}
Hint

Each call to fgets reads one line, and returns NULL at the end of the file.

Solution

Output: lines = 3. Three lines were written, each ending with \n, so fgets succeeds three times.

E2w erases, a appends

Medium Predict the output CO4 · BCL L-4 Analyze

The file is opened three times. What does it contain at the end?

#include <stdio.h>
int main()
{
    FILE *fp;
    char buf[50];
    fp = fopen("m.txt", "w");
    fprintf(fp, "first");
    fclose(fp);
    fp = fopen("m.txt", "w");
    fprintf(fp, "second");
    fclose(fp);
    fp = fopen("m.txt", "a");
    fprintf(fp, "third");
    fclose(fp);
    fp = fopen("m.txt", "r");
    fgets(buf, 50, fp);
    fclose(fp);
    printf("%s\n", buf);
    return 0;
}
Hint

Mode "w" empties an existing file; mode "a" adds to the end. Try the same sequence in the file simulator above.

Solution

Output: secondthird. The second "w" erases "first". The "a" adds "third" after "second".

E7Reading a file that is not there

Medium Find the bug CO4 · BCL L-4 Analyze

This program works on the teacher's PC but crashes on a student's. What is missing?

FILE *fp = fopen("data.txt", "r");
int x;
fscanf(fp, "%d", &x);
printf("%d\n", x);
fclose(fp);
Hint

What does fopen return when the file does not exist in the current folder?

Solution

If data.txt is missing, fopen returns NULL, and passing NULL to fscanf or fclose crashes the program. Always test the pointer right after opening, and stop with a clear message.
