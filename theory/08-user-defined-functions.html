User-Defined Functions

A function is a named block of code that does one job. Write it once, call it as often as needed, and watch each call get its own frame on the stack.

Practise in the lab: Lab 08 · Functions and Recursion

Why functions

Functions come in two kinds. Predefined (standard) functions such as printf(), scanf(), pow() and rand() are already written and compiled into the C library; including the right header (stdio.h, math.h) gives the compiler their prototypes, and the linker adds their code. User-defined functions are written by the programmer for the program's own tasks.

Splitting a program into functions avoids repeating code (and the errors that come with repetition), lets you reuse code in other programs, and makes a large program easier to plan, read and test.

A library function is a black box: you give it arguments and it returns a value. You need to know what it does, not how.

Anatomy: prototype, definition, call

To use your own function you (1) declare it with a prototype, (2) define it (write its body), and (3) call it. Click the parts.









The slides label the parts with these terms, using a max() function:




Define a function
int max(int num1, int num2)   /* return type, name, formal parameters */
{                             /* the first line is the function header */
    int result;               /* function body starts */
    if (num1 > num2)
        result = num1;
    else
        result = num2;
    return result;            /* return value */
}


Invoke (call) it
int z = max(x, y);   /* x, y: actual parameters (arguments) */


  • return type: int
  • function name: max
  • formal parameters (the parameter list): int num1, int num2
  • name + parameter list form the function's signature
  • actual parameters (arguments): the values in the call, x and y




Declaration versus definition


The declaration (prototype) only announces the function: int max(int num1, int num2); ends with a semicolon and has no body. The definition is the full function with its body. A function may be declared many times but defined only once.




Matching arguments with parameters


The arguments in a call are matched with the parameters by position, not by name: the first argument goes to the first parameter, and so on. Their number and types must agree with the prototype; a value of a different type is converted (an int argument for a double parameter becomes a double).


    

  1. The function call should have matching arguments: the same number, in the same order, of compatible types.
    2. 

  2. With a prototype (ANSI C), a call with more or fewer actual arguments than formal arguments is a compile error. GCC reports:

    args.c:5:20: error: too many arguments to function 'add'
args.c:6:20: error: too few arguments to function 'add'
    3. 

  3. If an argument has a different data type, it is converted to the type of the formal argument (for example, int to double).
    4. 

  4. Without a prototype (old-style C) the compiler cannot check the call: extra arguments are ignored and missing ones receive garbage values. So always declare a prototype.

Example: nCr without and with a function


Number of permutations of n distinct objects taken r at a time: P(n, r) = n! / (n − r)!
Number of combinations of n distinct objects taken r at a time: C(n, r) = P(n, r) / r! = n! / (r! (n − r)!)


To compute nCr with n and r given by the user, the first version repeats the factorial loop three times.




With a factorial() function the logic is written once and called three times. Step through it: each call creates a new frame on the stack with its own x, fact and i; when the function returns, its frame disappears and the returned value replaces the call.





Parameters


A function can take any number of parameters. draw_rectangle() takes none, factorial(int x) takes one, and power(int a, int b) takes two. A function that returns nothing has the return type void.




Copies, not originals. a and b receive copies of x and y (pass by value). Changing a inside power() would not change x. Lecture 10 shows how pointers let a function change the caller's variables.



Scope: where a variable is visible


The scope of a variable is the part of the program where its name can be used. A variable declared inside a function (a local variable) exists only in that function, and only while it runs. A variable declared outside all functions (a global variable) is visible in every function below its declaration.




Can we do this?

void power(int a, int b);
int main()
{
    int x = 2, y = 8, z;
    power(x, y);
    printf("%d\n", result);   /* ? */
    return 0;
}
void power(int a, int b)
{
    int i, result = 1;        /* local to power */
    for (i = 1; i <= b; i++)
        result *= a;
}


No. GCC says:

scope.c: In function 'main':
scope.c:7:20: error: 'result' undeclared (first use in this function)
    7 |     printf("%d\n", result);
      |                    ^~~~~~


result belongs to power(). Inside main() the name does not exist.




Declared globally, result is visible in both functions. Watch the global variables box in the memory panel: power() writes to it and main() reads it.




Use globals sparingly. Any function can change a global variable, so a bug can come from anywhere. Passing values as parameters and returning results keeps each function self-contained.

Passing an array to a function


The slides point to a video on this. To pass an array, write the parameter with empty brackets, int a[], and pass the size separately, because the function cannot find out the length by itself. The call uses only the array name: sumArray(marks, 5). Unlike ordinary variables, the array is not copied: the function receives the address of the first element (Lecture 11 explains why), so changes it makes to the elements are visible in the caller.





A function that answers yes or no


Returning 1 or 0 lets a function be used directly in an if. As soon as a divisor is found, return 0; leaves the function, which also ends the loop.




Edge case. As written, is_prime(1) and is_prime(0) return 1 because the loop never runs. Add if (a < 2) return 0; at the start.

E1A function changes its copy
Easy Predict the output CO4 · BCL L-4 Analyze

#include <stdio.h>
void change(int x)
{
    x = x * 10;
    printf("in: %d\n", x);
}
int main()
{
    int a = 4;
    change(a);
    printf("out: %d\n", a);

}
Hint
The parameter x receives a copy of a.
Solution
in: 40
out: 4
change() multiplies its own copy. When it returns, the copy disappears and a in main is still 4 (pass by value).
E2Local or global?
Medium Predict the output CO4 · BCL L-4 Analyze
Two functions use the name n. What is printed?
#include <stdio.h>
int n = 10;
void f(void)
{
    int n = 3;
    n++;
    printf("%d ", n);
}
void g(void)
{
    n++;
    printf("%d ", n);
}
int main()
{
    f();
    g();
    f();
    g();
    printf("%d\n", n);
    return 0;
}
Hint
Inside f(), the local n hides the global one and is created fresh on every call. g() has no local n.
Solution
Output: 4 11 4 12 12. Each call of f() starts a new local n = 3 and prints 4. Each call of g() increments the global n, from 10 to 11 and then 12, which main prints at the end.

E7A function that forgets to return
Medium Find the bug CO4 · BCL L-4 Analyze
GCC compiles this with only a warning. What goes wrong when it runs?


int max(int a, int b)
{
    if (a > b)
        return a;
}
Hint
What does the function return when a <= b?
Solution
When a is not greater than b, control reaches the closing brace without a return. If the caller uses the result, the behaviour is undefined: it gets whatever happens to be in the return register, often a garbage value. -Wall reports control reaches end of non-void function. Every path of a non-void function must return a value.
